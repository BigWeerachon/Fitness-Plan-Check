# การเปลี่ยนแปลงสเปค (SPEC_CHANGES)

> **ไฟล์นี้มีผลเหนือ [`SPEC.md`](SPEC.md) ในทุกข้อที่ขัดกัน** — `SPEC.md` ห้ามแก้ (เป็นต้นฉบับ) การเปลี่ยนแปลงที่เจ้าของโปรเจกต์ตัดสินภายหลังจึงบันทึกที่นี่ ข้อใดใน SPEC ที่ไม่ได้ระบุในไฟล์นี้ยังใช้ตามเดิม
>
> รายละเอียดการตัดสินใจและผลกระทบในโค้ด: [DECISIONS.md](DECISIONS.md) D81, D81.2, D81.3, D82, D83

## การตัดสินใจของเจ้าของ — 2026-10-14: แอปออฟไลน์ล้วน ไม่มีคลาวด์ของเราเอง

**สรุป**

- แอปทำงานแบบ **ออฟไลน์และอยู่ในเครื่องเท่านั้น** ข้อมูลผู้ใช้ทั้งหมดอยู่ในฐานข้อมูล SQLite บนเครื่อง
- **ตัดออก:** Supabase ทั้งหมด (Auth, Postgres sync, RLS, migrations, Edge Functions `revenuecat-webhook` และ `delete-account`), sync engine / คิว outbox / เคอร์เซอร์ / สถานะซิงก์, Google Sign-In, Sign in with Apple, หน้าล็อกอิน, ล็อกเอาต์, การลบบัญชีบนคลาวด์
- **คงไว้ (เจ้าของเลือก "ซื้อได้โดยไม่ล็อกอิน"):** ทดลองฟรี 7 วัน → รายเดือน หรือซื้อขาด ผ่าน App Store / Google Play ด้วย RevenueCat แบบ **app user id นิรนาม** (configure โดยไม่ส่ง appUserID และไม่เรียก `logIn`/`logOut` เลย) — Paywall → เลือกแพ็กเกจ → ซื้อทันที; "กู้คืนการซื้อ" กู้ผ่านบัญชีสโตร์ (เครื่องใหม่/ติดตั้งใหม่); แคชสิทธิ์ + ผ่อนผันออฟไลน์ (B9) คงเดิม; กฎการล็อก (B3) คงเดิมตามรายการที่แก้ด้านล่าง; ข้อมูลไม่ถูกลบเมื่อสิทธิ์หมด
- **เพิ่ม (เจ้าของเลือก "ไฟล์สำรอง + กู้คืน"):** ตั้งค่า → "สำรองข้อมูล" (ไฟล์ JSON มีเวอร์ชัน ครบทุกตารางผู้ใช้ แชร์ผ่านหน้าแชร์ของระบบด้วย `expo-sharing` ให้ผู้ใช้เก็บเองใน Drive/LINE/Files/อีเมล) และ "กู้คืนจากไฟล์" (`expo-document-picker`; ตรวจ app id, เวอร์ชันรูปแบบไฟล์, ความเข้ากันได้ของ schema/migration, รูปแบบแถว; แสดงสรุป + ยืนยันแบบย้อนกลับไม่ได้; แทนที่ข้อมูลผู้ใช้ทั้งหมดในทรานแซกชันเดียว; ผิดพลาด = ไม่มีอะไรเปลี่ยน) ต้องเข้าได้แม้ถูกล็อก (เช่น เครื่องใหม่ก่อนกู้คืนการซื้อ) — อยู่ในหน้าบัญชี/ตั้งค่าที่เข้าได้เสมอ; ส่งออก CSV คงไว้
- **"ลบบัญชี" → "ลบข้อมูลทั้งหมดในเครื่องนี้"** (ลบตารางผู้ใช้ + ร่าง + แคช ยืนยัน 2 ขั้น ยังเตือนว่าไม่ยกเลิกการสมัครในสโตร์พร้อมทางลัดไปหน้าจัดการสมาชิก)
- **Schema:** คงคอลัมน์ `ownerId`/`updatedAt`/`deletedAt` ไว้ (ลดความเสี่ยงจากการรื้อ) โดย `getOwner()` คืนค่าคงที่ `'local'`; ลบตาราง `sync_outbox` / `sync_state` ด้วย drizzle migration ที่รักษาข้อมูลเดิมของผู้ใช้ตอนอัปเดต

## กฎใหม่ที่ไม่มีใน SPEC เดิม

1. **ไฟล์สำรอง (D82):** `fitnese-backup-YYYY-MM-DD.json` = `{ format: 'fitnese-backup', formatVersion, schemaVersion, appVersion, exportedAt, settings, tables }` ไม่เข้ารหัส ไม่มี `ownerId` และไม่มีแถวที่ถูก soft delete · กู้คืนรับไฟล์ที่ `formatVersion`/`schemaVersion` ไม่ใหม่กว่าแอป (ไฟล์จาก schema เก่าเติมค่าเริ่มต้นให้คอลัมน์ที่ขาด) · ขนาด ≤ 50 MB · การกู้คืนแทนที่ข้อมูลทั้งหมด ไม่รวม (merge)
2. **ความเป็นส่วนตัว:** ข้อมูลที่ออกจากเครื่องมีแค่ข้อมูลการซื้อที่ RevenueCat ได้รับ (รหัสนิรนาม + ประวัติการซื้อ + ข้อมูลทางเทคนิคของการเชื่อมต่อ) — privacy manifest, ป้ายสโตร์ และนโยบายฯ ต้องตรงกัน ถ้าในอนาคตจะเพิ่มคลาวด์หรือส่งข้อมูลอื่นออกจากเครื่อง ต้องเป็นการตัดสินใจใหม่ของเจ้าของและบันทึกในไฟล์นี้
